# Hymnix Orbit 账户与 GitHub 登录 —— 策划稿

状态：草案，等你确认后开工。
范围：给桌面端增加「用 GitHub 账号登录」的账户体系。
底线：**不登录也能完整使用本机所有功能**；登录是加值，不是门槛。

---

## 1. 为什么要有登录（先定价值，再谈技术）

本地优先的桌面应用加账户，只有一个理由成立：**让身份带来跨设备/跨人的连续性**。具体到本项目，登录后能做的事按价值排序：

1. **身份**：头像、@用户名、设备列表；共享页里别人看到的是「@someone 的电脑」，而不是一串 IP。
2. **同步**（需要轻后端）：会话历史、界面设置、提示词预设、主题；**API Key 永不同步**。
3. **聊天分享**：把一段对话生成只读链接（可选，公开/私密）。
4. **授权/订阅**：以后若要做付费模型额度或云同步额度，这里是入口（第一版不做）。
5. **社区资产**：共享主题、预设、提示词包（后期）。

如果以上四项你都觉得“暂时不需要”，那就不该做登录——加了只会增加攻击面和使用摩擦。**这是第一个需要你确认的问题。**

---

## 2. 身份方案：GitHub 设备授权码（Device Flow）

桌面应用没有可信的回调地址，标准做法是设备流：

```
① 点「用 GitHub 登录」
② 应用显示 8 位码（ABCD-1234）并打开 https://github.com/login/device
③ 你在浏览器输入码 → 授权
④ 应用轮询拿到 access_token（gho_…）
⑤ 主进程 GET /user → login、name、avatar_url
⑥ 界面显示「已登录为 @xxx」；token 加密存本机
```

- 应用里只有公开的 `client_id`，**没有 client_secret**。
- token 用 Electron `safeStorage` 加密后写进现有 `orbit-credentials.bin`（沿用 `CredentialsApi`）。
- 渲染层只拿得到「用户名 + 头像 + 登录态」，拿不到 token。
- 支持「粘贴 PAT」作为兜底（离线安装、企业网络受限、没有 OAuth App 时）。

**前置条件**：需要一个 GitHub OAuth App 的 `client_id`（勾选 Enable Device Flow）。这个只能你在 GitHub 上注册一次。

---

## 3. 权限（scope）分两级，登录只给最少的

| 用途 | scope | 说明 |
|---|---|---|
| **仅登录/身份**（推荐默认） | `read:user` | 只读用户名、头像、公开资料。不碰任何仓库 |
| 仓库功能（后续独立授权） | `repo` 或 `public_repo` | 列仓库、克隆、推送、开 PR 时才申请，可在设置里单独勾选 |

关键设计：**登录本身只要 `read:user`**。仓库权限走第二次、显式的授权，用户不点就不申请——避免“登个录要我的全部仓库”。

---

## 4. 无后端的同步方案（如果要做同步，选一个）

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 不做同步**（第一版推荐） | 只存登录态与头像 | 零后端、零隐私风险 | 换设备要重新配置 |
| **B. GitHub Gist 同步** | 把会话/设置加密后写进用户私有 Gist | 零后端、身份天然对齐 | 隐私差（数据在微软），大文件不适配 |
| **C. 轻后端**（Cloudflare Worker / Supabase / 自托管） | 账号体系 + 对象存储 | 可控、可做分享链接与订阅 | 要运维、要域名、有合规成本 |
| **D. 复用现有 host/gateway 服务** | 用户自己的机器当同步端 | 无第三方 | 只有多设备同一局域网时好用 |

我的建议：**第一版选 A（纯登录，不碰数据）**；同步留到有明确需求时再上 C，并且同步内容只允许白名单（会话/设置/预设），API Key 与设备凭据永不外发。

## 5. 界面落点（具体到控件）

```
┌─ 标题栏右上 ────────────────────────────┐
│  [待审批 2] [任务 1]  (头像) @username  │   ← 未登录时显示「登录」
└────────────────────────────────────────┘

侧栏底部（现有「设置 / 本地模式」区）：
  未登录：  ◯ 未登录 · 用 GitHub 登录
  已登录：  (@avatar) @username   [账户设置] [退出]

设置 → 新增「账户」一节：
  - 登录状态 / 头像 / 用户名 / GitHub 主页链接
  - 「授权仓库访问」开关（点了才申请 repo scope）
  - 设备列表（本机 / 共享中的其他设备）
  - 退出登录（清除本机 token 与头像缓存）
共享页：
  - 「作为主机」显示 @username，访客看到的是「@username 的电脑」
```

登录弹窗流程：点登录 → 显示 8 位码（可一键复制）+「在浏览器中打开」+ 倒计时 15:00 → 轮询中 → 成功关闭；失败（拒绝/过期/网络）给出可操作的原因与重试。

## 6. 安全与隐私（写成硬约束）

1. token 只在主进程，不进渲染层、不进日志、不进崩溃报告。
2. 不把 token 拼进 URL 或命令行参数。
3. 退出登录 = 删除加密记录 + 删除头像缓存 + 清 git 凭据缓存。
4. token 失效（401）→ 自动转未登录并提示重新登录；不静默重试。
5. 设备流必须遵守 `interval` 与 `slow_down`，过期（15 分钟）停止轮询。
6. 若做同步：内容加密后再上传，密钥由 token 派生；服务端拿不到明文。
7. 记录一次审计日志（登录/退出/授权变更），只存本机。

---

## 7. 失败路径（都要有 UI，不能白屏）

| 情况 | 表现 |
|---|---|
| 用户拒绝授权 | 「你取消了授权」+ 重试按钮 |
| 8 位码过期 | 「验证码已过期」+ 重新生成 |
| 网络不通 / 被墙 | 「连不上 github.com」+ PAT 兜底入口 |
| 企业 SSO 未授权 | 提示去 GitHub 组织设置里给该 OAuth App 授权 |
| token 被撤销 | 转未登录，保留本机数据 |
| 本地存了登录态但离线 | 显示「离线 · @username」，功能照常 |

## 8. 里程碑与工作量

| 期 | 内容 | 工期 | 验收 |
|---|---|---|---|
| **P1 登录态** | 设备流 + 头像/用户名 + 退出 + PAT 兜底 + 失败路径 | 1 天 | 六种失败路径都能操作；重启仍登录；渲染层拿不到 token（代码审查 + 断言） |
| **P2 身份融合** | 共享页显示 @username；设备列表；设置「账户」节 | 0.5 天 | 访客看到 @username；断开后恢复匿名 |
| **P3 仓库授权**（可选） | 单独申请 repo scope；仓库列表/克隆 | 1.5 天 | 不点授权则全程无 repo 权限 |
| **P4 同步**（可选） | 选定的轻后端；白名单内容同步 | 3 天+ | 冲突策略明确；API Key 断言不出网 |

P1+P2 是这次的最小交付，约 1.5 天。

---

## 9. 风险

- **必须有 OAuth App**：client_id 得你在 GitHub 注册；不给就只能先做 PAT。
- 公开 client_id 属于公开客户端常态，但要注意 GitHub 的 OAuth App 速率与滥用规则。
- 加入登录会引入「账号相关支持成本」（登不上、被撤销、组织策略），要有清晰的引导文案。
- 如果以后做同步，隐私承诺必须写进 README 与设置页。

---

## 10. 需要你拍板的五个问题

1. **登录用来干什么**：只做身份（头像/@名/设备列表），还是要做跨设备同步？
2. **client_id**：你去注册 OAuth App（推荐），还是第一版只做 PAT？
3. **scope**：登录只申请 `read:user`（推荐），仓库权限以后单独授权，可以吗？
4. **是否要求登录才能用**：我的建议是**绝不**——游客可用全部本机功能，登录只加值。你同意吗？
5. **共享页实名**：登录后是否把主机名显示为 @username？（会暴露 GitHub 用户名给访客）

确认这五条，我就按 P1 → P2 做，每一步给你截图、失败路径演示和门禁结果。
